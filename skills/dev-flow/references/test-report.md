# 测试结果文档

测完统一出一份，给用户看测试结果。每个测试点都要有对应的截图或日志，以及说明。

## 存放

- **放在仓库外**，不进 git，不会被提交，也不会被推送；长期保存，以后能翻出来对照。
- 位置按档案里写的（档案指定的位置也必须在仓库外）。档案没写的，用默认位置：

  ```
  ~/Documents/TestReports/
  └── <项目名>/                   仓库文件夹的名字
      ├── 报告清单.md              这个项目的所有测试报告，一份一行：日期、主题、结论、链接
      └── <日期>-<主题>/           比如 2026-10-15-固件升级完成页，主题用几个中文字说清测的是什么
          ├── report.md           报告正文
          ├── index.html          同内容的网页版
          ├── 01-<简短名>.jpg      截图（压缩过的）：两位序号对应「一览」里的编号，简短名几个字说清是什么
          └── 01-<简短名>.log      这一项的日志摘录，有才放
  ```

  - 同一天同一个主题再测一次，目录末尾加 `-2`、`-3`，不覆盖之前的。名字里不用空格。
  - 写完在「报告清单.md」末尾追加一行，旧的行不改；没有这个文件就新建，第一行写表头 `| 日期 | 主题 | 结论 | 报告 |`。
- 截图和日志跟报告放在同一个目录，报告里用相对路径引用。
- 截图压缩后再放进来：原图存在报告目录外的临时目录，量颜色、尺寸用原图。放进报告目录的，长边超过 1600 像素的缩到 1600，转成质量 75 的 JPEG（iPhone 截图从约 2.5M 降到约 100K）：macOS 用 `sips -Z 1600 -s format jpeg -s formatOptions 75 <原图> --out 01-<简短名>.jpg`，其他系统用 ImageMagick 或 Pillow。要看像素细节的（比颜色、1 像素的线），另截那一块原尺寸的局部图，存 PNG。
- 写完告诉用户报告在哪、怎么打开。档案没写的，默认在报告旁边生成一份同内容的 index.html，在项目文件夹（`~/Documents/TestReports/<项目名>/`）起本地 http 服务（端口被占就换一个），回复里给这次报告的 http 链接；往期的报告也能在浏览器里点开。

## 格式

全文用大白话，少用术语；非用不可的，第一次出现时在括号里解释。不懂技术的人只看开头的结论和一览就能明白，开发再看后面的详情。

```markdown
# <功能名> 测试结果（<日期>）

**结论**：<一句大白话：能不能用、还差什么>
**需要你做的**：<没有就写"无">
- <比如：在设备上感受震动强度合不合适（见第 5 项）>
**测的版本**：<分支> 的 <提交号>（另有没提交的改动就写明）；拍板记录在 <路径>（没有就不写）

| 2 | …… | ⚠️ 需要你确认 |

## 说好的都做到了吗（中、大规模）
拍板摘要每段一张表，段名写在表头，下面照摘要的编号 1、2、3 往下列，每行写这条的小标题；不合并、不改写、不跳号。依据、影响范围、已知风险三段是背景，不列。拍板摘要里没有、做的时候加上的，另起一张「后来加的」表，也从 1 编号：开工后用户新定的，和自己补的小处理（比如多处理了一种出错情况）都算。写完对一遍：除了那三段，摘要里每一段都要有一张表，条数和摘要一样；那三段不要有表。

结果只用这五种：
- ✅ 做到
- ❌ 没做到：说明里写原因。
- 🔄 有调整：做了，但和摘要说的不一样，说明里写清哪里不一样；想让用户定要不要改回来，也在说明里问，不标需要你确认。
- ⚠️ 需要你确认：要用户判断或拍板的，比如要人感受的效果、审查发现的新问题。和一览里的一样，也算进开头的「需要你确认 X 项」。
- ⏭️ 还没到：写报告时还没到时候做的，比如提交、问怎么合并；说明里写什么时候做，不算进「需要你确认」。
  ```
